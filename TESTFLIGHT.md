# Test Immersed on iPhone with TestFlight

The owner confirmed Apple Developer Program membership on 2026-11-05. This repository is linked to the Expo project [@somamill/immersed](https://expo.dev/accounts/somamill/projects/immersed); `app.json` contains its real project ID. The iOS bundle identifier is `com.somamill.immersed`. The TestFlight GitHub workflow remains manual. A fresh non-interactive production build attempt on 2026-11-11 advanced the remote build number to 5, then stopped: Expo reported that iOS distribution credentials are not set up and that the production environment has no public service-origin variable. EAS requires one interactive Apple authentication on a trusted terminal or manually supplied signing credentials in the [Expo project credentials settings](https://expo.dev/accounts/somamill/projects/immersed). A signed build, App Store Connect app record and TestFlight install have **not** been verified yet.

## Before the first build

1. In App Store Connect, accept pending agreements, register the bundle ID if needed, and create an app record using `com.somamill.immersed`. Record the numeric Apple app ID (`ascAppId`), which differs from the Apple Team ID and login email.
2. With the current server-backed app, put the stable HTTPS language service online and verify dictionary search, Japanese caption access and the captionless-video acceptance test from [RELIABILITY.md](RELIABILITY.md). A proposed [local processing path](docs/LOCAL_FIRST.md) can replace this dependency only after it is implemented and tested. Set `EXPO_PUBLIC_IMMERSED_API_ORIGIN` to the public HTTPS origin in the Expo **production** environment. The app embeds this public address at build time. Do not use a temporary Expo URL.
3. From an authenticated terminal, run `npm ci`, then `npx eas-cli@latest build --platform ios --profile production`. Let EAS manage the Apple signing certificate and provisioning profile for your Apple team. Complete Apple authentication in the official EAS/Apple flow; never send passwords, private keys, two-factor codes or tokens in chat.
4. After the first successful signed build, upload to TestFlight with `npx eas-cli@latest submit --platform ios --profile production`. Set `submit.production.ios.ascAppId` in `eas.json` or the `ASC_APP_ID` GitHub variable once the app record exists.
5. On your iPhone, install the processed TestFlight build. Check real video playback, caption language and timing, dictionary and saved words, background/foreground behavior and network recovery. The owner requires automatic Japanese subtitles for every YouTube video; this beta would not yet meet that requirement. See [App Store preparation](docs/APP_STORE.md) for the remaining public release gates.

Apple Developer membership allows signing and TestFlight, but Expo build quotas may still apply. A completed EAS upload means the binary reached App Store Connect; it does not mean Apple approved or published the app.

## Optional manual GitHub workflow

After one interactive signing/upload setup, add an Expo access token as the repository secret `EXPO_TOKEN` and the numeric Apple app ID as repository variable `ASC_APP_ID`. Select Actions → **Send iPhone update to TestFlight** → Run workflow. It queues a new EAS build with automatic TestFlight upload; a successful workflow means it was queued, so check EAS and App Store Connect processing before opening TestFlight. No token or Apple credential belongs in this repository.

Sources: [Expo iOS production build](https://docs.expo.dev/tutorial/eas/ios-production-build/), [Expo submission](https://docs.expo.dev/submit/ios/), and [TestFlight distribution](https://docs.expo.dev/submit/testflight/).
